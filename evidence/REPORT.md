## Реализовано

Исполнитель libtorrent TCP/UDP + FFmpeg и собственный HTMLVideoElement/HLS.
Iframe, чужие онлайн-плееры и прямые видеосервисы отсутствуют. Точные IMDb из
исследования сохранены, включая Death Note 2006 и Shrek 2001. Сезон/серия
передаются отдельно. Список эпизодов запрашивается у Cinemeta; при отказе
резервные номера явно названы номерами запроса, не подтверждённым каталогом.

Поиск Comet и TorrentsDB, дедупликация с сохранением происхождения, выбор
исходного качества/заявленной озвучки, проверка infohash, исходного fileIdx,
пути и размера. Неверный или неоднозначный эпизод отказывается запускаться.
Исследовательские карты 20 эпизодов перепроверены по реальным info dictionary.
Пути относительно info.name и полные пути libtorrent согласованы без
произвольного сравнения одного basename.

ffprobe читает реальные потоки. Русский язык проверяется по language/title;
неизвестное значение не превращается в русский. FFmpeg готовит H.264/AAC
480/720/1080 без увеличения разрешения. HLS VOD с отдельными сегментами
поддерживает дальнюю перемотку и смену потока с сохранением позиции. На iOS
предусмотрены HLS.js/Managed Media Source и native HLS fallback, playsinline,
отдельная кнопка возобновления после отказа autoplay. Это реализация,
не физическая проверка Safari.

При отказе metadata, файла, языка, FFmpeg или fatal HLS автоматически выбирается
следующая раздача. До 8 попыток за запуск; таймауты ограничены. Отмена и смена
произведения инвалидируют старые обработчики. Экспорт не содержит подписанного
playback-задания, временного URL или IP пиров.

## Что проверено положительно

`live-search-matrix.json`: **48/48 настоящих запросов** опубликованного API
дали torrent-кандидаты. 24 комбинации × 2 аддона. Все 10 произведений, S1E1/S1E2,
дополнительно S2E1/S2E2 для Дандадана, Фрирен, Fallout и Breaking Bad.

`local-torrent-control.json`: собственный 150-секундный ролик, настоящий
TCP-сидер libtorrent на loopback. Получены SHA-1-проверенные части. Первый
сегмент получен до полной загрузки. Сегмент с позиции 120 с декодируется как
H.264/AAC. Повторное чтение после очистки кэша проверяется отдельно.

`browser-control.json`/PNG: Chromium/Linux, свой плеер; 960×720, кадры и время
двигаются, дальний seek в незагруженную область, смена двух известных звуковых
потоков, качество 720→480, реальный ended. Первая намеренно неверная metadata
даёт отказ, после которого автоматически стартует следующий реальный torrent.
Поиск этого опыта **синтетический**, медиа — собственный сгенерированный ролик
с контрольными тонами. Это не прослушивание русской речи коммерческого релиза.

Unit-проверки отделены: три теста нормализации имеют префикс synthetic; пять
Python-проверок включают реальные metadata и контрольный TCP-транспорт.

## Что не заработало на подборке

В `live-play-*.json` сохранены настоящие попытки опубликованного исполнителя.
У Слова пацана и Fallout проверены metadata, размер и правильный файл S1E1,
но **0 пиров, 0 видеобайт**. У остальных проверенных кандидатов — timeout
metadata/BEP9; где диагностика ещё не была добавлена, значения байтов оставлены
неизвестными, не дописаны задним числом нулями.

На зафиксированных отказах: DHT nodes 0, native tracker errors 180
`skipping tracker announce (unreachable)` и 16 `Device or resource busy`.
Отдельный стандартный HTTPS announce на двух публичных трекерах также не
вернул доступных пиров. Это наблюдения данной среды/раздач, а не доказательство
глобальной недоступности этих раздач или запрета BitTorrent у всех клиентов
Vercel. Конкретная административная причина сетевого отказа не установлена.

Проверен другой путь metadata: HTTPS-кэши с проверкой infohash. У itorrents.org
обнаружен redirect к itorrents.net; отдельный HTTPS GET .net дал валидный
torrent выбранного Shrek, совпадающий по infohash. Метаданные не считаются
видеобайтами; повтор через опубликованный API подтвердил свежие metadata и правильный файл Shrek. Чтение видео завершилось PIECE_TIMEOUT: 0 пиров, 0 видеобайт (сборка 07448dc).
Torrage вернул 403, btcache — невалидное/не соответствующее hash тело.

Ранние `RESEARCH_FILE_MAP_MISMATCH` были дефектом сравнения корневого пути и
исправлены. Ранние `EXECUTOR_CAPACITY` связаны с ограничением двух сеансов и
не доказывают отказ поставщика; выполнены новые ограниченные пробы. Ошибочная
ранняя команда с неправильным base URL сохранена как
`INVALID_PROBE_TARGET_CLIENT_BUG`, а не сетевой результат Vercel.

## Публикация и серверные зависимости

Репозиторий Test-video изначально содержал только README. Старый
MawrikBorug/kadr-video-lab прочитан, не изменён. Основной КАДР не изменён.

GitHub отклонил включение Pages (403). Пользователь предоставил доступ к
команде Vercel, где создан только новый проект test-video. GitHub Login
Connection отсутствует, поэтому выполнена прямая загрузка соответствующих
исходников с SHA. Автодеплой при будущих push не настроен. Проверенный
публичный production alias — test-video-taupe.vercel.app; другой alias команды
может требовать Vercel Authentication.

Vercel предоставляет Python Functions и трафик. Настроено 300 с на вызов,
кэш 256 МиБ на экземпляр, до 2 torrent-сеансов. Между экземплярами постоянной
affinity нет: подписанное задание позволяет восстановить выбранный torrent.
Непрерывность длинного фильма на такой схеме не доказана. Платный тариф,
подписка или карта не подключались. Текущий платёжный план/остаток квот
команды использованным API не подтверждён; безлимитная бесплатность не заявлена.

Есть Dockerfile для размещения исполнителя и поле HTTPS-адреса в стенде.
Ноутбук пользователя сервером не назначался. Готового разрешённого постоянного
бесплатного сервера с доказанным доступом к торрент-пирам в имеющихся
подключениях не найдено.

## Блокер продолжения

Для завершения требуется доступный облачный исполнитель с разрешённым
исходящим BitTorrent TCP/UDP и ресурсами FFmpeg; текущие сетевые пробы этого
не подтвердили. Минимальный следующий доступ — HTTPS/развёртывание такого
исполнителя либо административная возможность диагностировать и разрешить
его исходящий P2P. Нужен не новый IMDb, не список magnet и не платный debrid.
Конкретный платный сервер без решения владельца не выбирался.

После появления этого доступа нужно повторить настоящие медиапробы,
подтвердить выбор/звучание русского потока, качество, дальний seek, конец
произведения и затем физические iPhone Safari/PWA. Пока эти пункты NOT_RUN
или BLOCKED, полную готовность заявлять нельзя.

Финальный браузерный сценарий дополнительно выявил гонку: поздняя загрузка
сводки инициализировала карточку заново и могла отменить уже начатый поиск.
Добавлена проверка поколения; регрессия с задержанным ответом проверяет, что
выбор Death Note S1E2 и поиск не сбрасываются. Промежуточный автоматический
таймаут и успешный повтор с задержками не выдаются за медиапроверку.
